# 关键不变量

以下约束是当前实现必须保持的事实。

## 金额与账目条目

- 表单和 `Ledger` 输入边界的金额为十进制字符串；领域逻辑不以 JavaScript 浮点数解析、比较或累计金额。
- `ledger_entries_v1.amount` 始终为正整数分，SQLite 的 `STRICT` 表和约束拒绝不符合该规则的数据。
- 汇总在分单位上以安全整数运算；收入、支出和结余不得改用浮点累计。
- Ledger 只接受 `0.01` 至 `1,000,000.00`、最多两位小数的十进制字符串，不进行隐式舍入。
- 描述写入前会去除首尾空白，且不能为空、长度不得超过 500 个字符。

## 账目条目可见性与时间

- 删除账目条目会写入 `deleted_at`，不会物理删除该记录。
- Ledger 的列表、汇总和更新均排除 `deleted_at` 非空的记录。
- `date` 输入必须是有效的 `YYYY-MM-DD` 自然日，且不得晚于设备本地当天。
- 创建和更新时 Ledger 写入 ISO 8601 格式的 `created_at`、`updated_at`；创建的记录从未删除状态开始。

## 持久化实现

- 原生端通过 `ledger_schema` 表按版本执行 SQLite 迁移；建表、索引和版本写入在同一个排他事务中完成。
- 数据库文件固定为 `bookkeeping-native-v1.db`，只在 iOS 与 Android 上使用。
- `snapshot()` 的列表和汇总来自同一 SQLite 事务内取得的可见条目，不能拆成可能观察不同状态的独立读取。

## 应用状态与测试重置

- 创建、更新和删除成功后，Ledger UI 重新读取一个完整快照，避免列表与汇总显示不同步的数据。
- Maestro 每个流程通过原生应用的 `clearState` 建立干净状态；具体方式见 [端到端测试说明](../../tests/e2e/README.md)。
