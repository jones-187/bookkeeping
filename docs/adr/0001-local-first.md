# Local-First 作为数据与交互原则

## 状态

Accepted

## 背景

个人财务数据具有隐私敏感、频繁访问和高可靠性要求。把核心记账流程建立在远程请求之上，会让网络质量和服务可用性直接影响记录与查看账目条目的能力。

纯本地应用最简单，但可能限制未来的备份或多设备体验；以服务端为中心则便于集中管理，却削弱离线能力和用户对数据位置的控制。

## 决策

核心记账流程采用 Local-First 原则：

- 用户操作首先作用于设备本地数据
- 本地数据足以支持当前核心用户流程
- 远程能力只能作为备份、同步或协作增强
- 远程失败不得阻塞已有本地数据的读取和维护

本决策不预先规定同步协议、冲突解决算法、远程数据库或身份系统。它们只有在对应需求和约束明确后才能单独决策。

## 后果

- 应用在离线状态下仍能提供核心记账能力
- 数据迁移和本地完整性成为高风险工程区域
- 未来同步必须适应本地先发生的写入，而不能把本地存储降级为远程缓存
- 多设备一致性和备份能力需要后续独立设计，不能从本决策直接推导
