# ADR-005: React Native E2E 测试策略

## 状态

已接受

## 背景

React Native 的核心目标是跨平台开发（iOS、Android、Web），但某些原生功能在 Web 平台上并不完全支持。例如：

- `@react-native-community/datetimepicker` 在 Web 上没有原生实现
- 许多原生模块（相机、传感器等）在 Web 上行为不同或完全不可用

## 决策

**E2E 测试必须在真实设备或模拟器上进行，不应依赖 Web 平台。**

具体原则：

1. **不因 Web 测试失败而修改源码** - 如果某功能在原生平台正常工作，但 Web 上有问题，不应修改源码来适配 Web
2. **E2E 测试使用 Maestro 连接模拟器/真机** - 这是 React Native 应用的正确测试方式
3. **Web 支持是次要的** - 如果 Web 版本有功能缺失，这是可接受的权衡

## 原因

1. **产品定位** - 本应用主要面向移动端用户，Web 版本是次要的
2. **避免过度工程** - 为 Web 平台添加 polyfill 或替代实现会增加代码复杂度和维护成本
3. **保持原生体验** - 强制使用原生组件可以保证最佳的用户体验
4. **测试真实性** - 在真实设备上测试才能发现真正的问题

## 后果

- E2E 测试需要配置 Android 模拟器或 iOS 模拟器
- CI/CD 流水线需要包含移动设备测试环境
- Web 版本可能存在功能限制，这被视为可接受
