# 风险区域

最后更新：2026-04-05

本文件标记需要额外小心和审查的高风险区域。

## P0：货币正确性

- 不要使用浮点数进行金额存储或运算
- 确保确定性的舍入行为
- 验证负数、零和大金额边界情况

**当前状态**：✅ 已实现
- `Money` 工具类使用整数（分）存储
- 完整的单元测试覆盖
- Service 层验证金额 > 0 且 < 100万

所需检查：

- ✅ 货币运算和舍入边界的单元测试
- ✅ 无效格式的输入验证测试

## P0：数据迁移

- 迁移应尽可能向前安全且可逆
- 永远不要将迁移成功与远程服务可用性耦合
- 回填步骤必须是幂等的

**当前状态**：✅ 已实现
- 使用 `schema_version` 表跟踪版本
- 迁移测试已通过

所需检查：

- ✅ 在干净数据库上的迁移测试
- ⏳ 从先前架构快照的迁移测试（阶段 2 引入迁移时）

## P1：Local-First 同步

- 离线操作不应被同步失败阻塞
- 冲突解决必须明确且可重现
- 版本/时间戳假设必须记录在案

**当前状态**：⏳ 未实现（阶段 4）

所需检查：

- 冲突情况的集成测试
- 重复同步有效负载的重试/幂等性测试

## P1：报表/汇总

- 总计必须与账目来源真相匹配
- 时区边界可能会扭曲每日/每月报表

**当前状态**：⚠️ 基础实现
- `getSummary()` 实现总收入、总支出、结余计算
- 测试已通过

所需检查：

- ✅ 汇总计算测试
- ⏳ 围绕日/月边界和时区转换的测试（阶段 3）

## 审查规则

触及 P0 区域的变更需要：

- 专注的 PR 范围
- PR 描述中明确的不变量检查清单
- 至少一名未编写变更的审查者
