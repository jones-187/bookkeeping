# 原生账目 MVP

## 状态

Accepted

## 来源

本规格落实 Local-First 产品方向和已确认的账目领域词汇，并为原生账目 MVP 提供唯一的行为合同。

## Outcome

在 iOS 和 Android 上提供离线可用的本地账目记录能力。用户可以新增、编辑、删除账目条目，并在同一个一致快照中查看条目列表、收入、支出和结余。

## Non-goals

- 不支持 Web 平台。
- 不提供 Go 服务、HTTP 接口、同步、备份或远程账户。
- 不提供分类、筛选、搜索、导入导出或多人协作。
- 不为当前开发数据提供迁移兼容性。

## Domain model impact

账目条目由唯一标识、收支方向、正整数分金额、描述、发生日期及软删除状态组成。

- 收入增加结余，支出减少结余；金额本身不以正负号表达方向。
- 领域计算和持久化均使用正整数分；不得以浮点数累计、比较或持久化金额。
- 用户输入金额为十进制字符串，只有通过解析后才能成为金额值。
- 发生日期是本地日历日期，不是时间戳。

## User-visible behaviour

- 用户可创建、编辑和删除账目条目。
- 新增表单默认使用设备本地当天日期，不得从 UTC 日期字符串截取。
- 金额输入必须是十进制字符串，取值范围为 `0.01` 至 `1,000,000.00`，且最多两位小数；不合法输入被拒绝，不进行隐式舍入。
- 日期必须是实际存在的本地日期，格式为 `YYYY-MM-DD`，且不得晚于当天。
- 描述在首尾空白移除后必须为 1 至 500 个字符。
- 删除为软删除；常规列表和汇总不显示、不计算已删除条目。
- 列表按发生日期倒序排列；发生日期相同时，后新增的条目排在前面。
- 列表、总收入、总支出和结余来自同一个一致快照。
- 结余为收入减支出；负结余必须显示负号。
- 本地读写在离线时仍可用；远程能力不存在，也不能成为本地读写的前提。

## Data and migration

数据仅存储在设备本地的 SQLite 数据库中。当前没有用户或需要保留的生产数据，因此重建 schema `v1`，不承担对现有开发数据的迁移兼容性；schema 创建和版本记录必须在同一事务内完成。

## Interfaces

应用 UI 仅通过 `Ledger` 模块读取快照和执行新增、编辑、删除操作。模块对外不暴露 SQL、数据库行类型或平台存储 API。平台装配、SQLite 连接、时钟和标识生成由应用 composition root 提供给模块。

## Failure and recovery

- 输入校验失败时，不写入任何数据，并向用户显示可理解的错误。
- 本地写入失败时，操作必须原子地成功或失败，失败后保留原有账目数据。
- 软删除后的条目不参与常规查询；当前 MVP 不提供恢复入口。
- 不存在远程写入或同步失败，因此远程故障不影响本地恢复和继续记账。

## Acceptance criteria

- iOS 和 Android 均使用本地 SQLite 完成新增、编辑、软删除、列表和汇总。
- 合法金额边界 `0.01`、`1,000,000.00` 被接受；零、负数、超上限、超过两位小数和非十进制字符串被拒绝。
- 不存在的日期和未来日期被拒绝；合法的当天及历史 `YYYY-MM-DD` 日期被接受。
- 跨 UTC 日期边界时，新增表单默认日期仍与设备本地日历日一致。
- 描述在 trim 后为空或超过 500 个字符时被拒绝。
- 删除后条目不在列表中，且不影响收入、支出和结余。
- 同一天连续新增的账目以较新的条目在前，排序不依赖随机标识或时间戳精度。
- 快照中的条目与汇总来自同一次读取；负结余以负号显示。
- 在无网络条件下，所有账目本地读写流程仍可执行。
